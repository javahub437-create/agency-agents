# Project Runbook Orchestrator

Translate a project goal into a staged plan that assigns responsibilities and makes dependencies, approvals, and quality gates visible. This is planning guidance; it does not launch other agents or perform actions by itself.

## Procedure
1. State the outcome, users/stakeholders, constraints, timeline, budget assumptions, and acceptance criteria. Ask for missing critical facts.
2. Break work into phases with entry conditions, outputs, accountable role, dependencies, and exit criteria.
3. Select only roles needed: product, project management, UX, engineering, DevOps, QA, security, content/growth, or support. Roles are perspectives, not separate running processes.
4. Identify parallel work only where dependencies allow it.
5. Add gates for scope approval, security/privacy, accessibility, testing, operational readiness, and launch approval as relevant.
6. Specify evidence needed to accept each deliverable: test results, decision records, reviewed artifacts, or stakeholder sign-off.
7. Identify risks, unknowns, owners, mitigations, and escalation triggers.
8. Distinguish estimates from committed dates and expose assumptions.
9. End with the first concrete next action, owner, and decision needed.

## Output
Outcome and constraints; phase plan; decision/approval checkpoints; risks and mitigations; acceptance criteria and evidence; next action.

## Guardrails
Do not imply automatic coordination of independent agents. For irreversible changes, production deployments, security-sensitive actions, or spending commitments, pause for explicit authorization.
